# BUG-002. Ответ входа не соответствует обязательной схеме TokenDTO

## Краткое описание

`POST /api/tester/login` нарушает [AUTH-02](../api-spec.md#auth-02).

## Оценка серьёзности и приоритета

Предлагаемая оценка, не утверждённая владельцем: **Severity — Major; Priority — P2**. Несовместимость обязательной модели мешает клиенту, построенному по OpenAPI, получить токен и его метаданные; для работы требуется отдельный адаптер.

## Окружение

- Стенд: `https://testslotegrator.com`.
- Воспроизведение: 2026-10-09, 14:06:12–14:08:08 +03:00 (Europe/Istanbul).
- Build/version/commit сервиса: **неизвестны**; источник версии развёртывания недоступен. `info.version: 1.0` в OpenAPI — версия документа, а не сборки backend.
- Источник требований: [сохранённый OpenAPI](../../src/test/resources/contracts/players-openapi.json), задание и явно принятые правила [спецификации](../api-spec.md).

Приведённые результаты относятся только к указанному прогону 9 октября 2026 года.

Повторный строгий прогон 9 октября 2026, 16:19–16:23 +03:00 подтвердил то же расхождение. Тесты выполнялись без преобразования падений в XFAIL; подготовка и резервная очистка завершились без ошибок.

Контрольный прогон 19:02–19:07 +03:00 воспроизвёл расхождение в контрактном тесте и в итоговой сверке целевого E2E.

## Предусловия

Действующие Basic-реквизиты и корректный `CredentialsDTO`. Проверка схемы выполняется независимо от расхождения HTTP-кода.

## Шаги воспроизведения

1. Выполнить корректный POST входа.
2. Проверить исходный JSON на наличие и тип обязательных полей `TokenDTO`, без alias и подстановки значений.

## Минимальный HTTP-запрос

Пример HTTP-запроса для повторения. Значения в угловых скобках необходимо заменить собственными реквизитами; Basic — это Base64 от пары `username:password`. Реальные пароли и токены в документ не включены.

```http
POST /api/tester/login HTTP/1.1
Host: testslotegrator.com
Authorization: Basic <BASE64_BASIC_USERNAME_AND_PASSWORD>
Content-Type: application/json

{"email":"<TESTER_EMAIL>","password":"<TESTER_PASSWORD>"}
```

## Фактический результат

Корень содержит `accessToken` и `user`. Обязательные `access_token`, `token_type`, `expires_in`, `scope` отсутствуют. Один из одного контрактных вызовов завершился failed.

## Ожидаемый результат

Объект с обязательными строковыми `access_token`, `token_type`, `expires_in`, `scope`; `access_token` непустой. Конкретное значение `token_type` и единицы `expires_in` здесь не придумываются.

## Влияние

Клиенты, построенные по опубликованной модели, не могут прочитать обязательный токен и его метаданные без частного адаптера.

## Технический анализ

- **Подтверждено:** имена и состав полей ответа расходятся с `TokenDTO`.
- **Неизвестно:** источник расхождения в серверном коде и семантика отсутствующих метаданных.
- **Рекомендация:** вернуть опубликованные обязательные поля с указанными типами; не исправлять проверку автоматическим alias `accessToken → access_token`.

## Обходной путь

Для функционального потока используется отдельная наблюдаемая модель `accessToken`; исходная контрактная модель сохранена. Успешное защищённое чтение подтверждает пригодность токена, но не соответствие `TokenDTO`.

## Доказательства

- Тест: [PublishedLoginContractIT#tokenMatchesPublishedSchema](../../src/test/java/qa/slotegrator/tests/contract/auth/PublishedLoginContractIT.java).
- Контрактная проверка на стенде завершилась failed: обязательные поля TokenDTO отсутствуют. Ниже приведены имена ключей без значений токена.

Минимальная очищенная выдержка; служебные поля и чувствительные значения опущены:

```text
POST /api/tester/login → 201
actual root keys: accessToken, user
missing required keys: access_token, token_type, expires_in, scope
```

Фрагмент ответа повторного прогона: HTTP **201**. Остальные поля опущены; значение токена скрыто.

```json
{"accessToken": "[скрыто]"}
```

## Проверка исправления

- Проверить все четыре поля по исходному JSON, без coercion и alias.
- Убедиться, что выданный `access_token` открывает защищённое чтение.
- Отдельно проверить AUTH-01 и отказ выдачи токена при неверных реквизитах.
