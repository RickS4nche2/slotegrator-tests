# BUG-005. OpenAPI описывает getAll как один объект вместо массива игроков

## Краткое описание

Документация ответа `GET /api/automationTask/getAll` нарушает [DOC-01](../api-spec.md#doc-01) и согласованность с [LIST-01](../api-spec.md#list-01).

## Оценка серьёзности и приоритета

Предлагаемая оценка, не утверждённая владельцем: **Severity — Major для дефекта документации; Priority — P2**. Клиент, сгенерированный по опубликованной схеме объекта, несовместим с фактически возвращаемой коллекцией. Работа самого списка при этом подтверждена.

## Окружение

- Стенд: `https://testslotegrator.com`.
- Контрактное воспроизведение: 2026-10-09, 14:17:46.676–14:17:48.018 +03:00 (Europe/Istanbul); отдельный предшествующий E2E — 13:36:35–13:36:57 +03:00.
- Build/version/commit сервиса: **неизвестны**; источник версии развёртывания недоступен. `info.version: 1.0` в OpenAPI — версия документа, а не сборки backend.
- Источник требований: [сохранённый OpenAPI](../../src/test/resources/contracts/players-openapi.json), задание и явно принятые правила [спецификации](../api-spec.md).

Приведённые результаты относятся только к указанному прогону 9 октября 2026 года.

Повторный строгий прогон 9 октября 2026, 16:19–16:23 +03:00 подтвердил то же расхождение. Тесты выполнялись без преобразования падений в XFAIL; подготовка и резервная очистка завершились без ошибок.

## Предусловия

Доступен исходный снимок OpenAPI. Для runtime-сверки — действующий Bearer и собственные подготовленные игроки.

## Шаги воспроизведения

1. В OpenAPI открыть схему ответа 200 операции `getAll`: указан один `PlayerResponseDTO`.
2. Прочитать список без собственных игроков, затем после их создания.
3. Сопоставить корневой тип JSON со схемой и требованием задания получить список.
4. Удалить собственные данные.

## Минимальный HTTP-запрос

Пример запроса с действующим токеном; токен заменяется локально. Для варианта с данными сначала создаются собственные игроки, после сверки они удаляются адресно. Чужие записи не удаляются ради получения пустого списка.

```http
GET /api/automationTask/getAll HTTP/1.1
Host: testslotegrator.com
Authorization: Bearer <ACCESS_TOKEN>
```

## Фактический результат

Независимый `listMatchesPublishedSchema` получил **200 и JSON-массив** при опубликованной схеме объекта и завершился **failed** по этому расхождению при отключённом xfail. Подготовка и резервная очистка прошли; последний getAll вернул 200 и `[]`. В предшествующем E2E все 41 чтение списка также вернуло массив, его содержимое проверено сквозным сценарием.

## Ожидаемый результат

Документация должна описывать **массив игроков** и корректную схему его элементов. Массив соответствует принятому продуктовому требованию; менять работающий `getAll` на одиночный объект для зелёного contract-теста нельзя.

## Влияние

Сгенерированный по Swagger клиент ожидает объект и не может корректно десериализовать список. Пустой список также не имеет описанного представления.

## Технический анализ

- **Подтверждено:** буквальная схема OpenAPI и форма runtime-ответа различаются. Задание требует коллекцию.
- **Неизвестно:** процесс генерации и публикации схемы.
- **Рекомендация:** исправить OpenAPI на `type: array` с `items`, согласовать модель ID с [BUG-003](BUG-003.md), сохранить поведение коллекции.

## Обходной путь

Функциональный клиент явно читает корневой массив и проверяет состав/поля. Это обход дефекта документации; ручное исправление исходного снимка без обновления источника не считается исправлением сервиса.

## Доказательства

- Источник схемы: [снимок OpenAPI](../../src/test/resources/contracts/players-openapi.json), ответ 200 `/api/automationTask/getAll`.
- Метод [PublishedPlayersContractIT#listMatchesPublishedSchema](../../src/test/java/qa/slotegrator/tests/contract/players/PublishedPlayersContractIT.java) выполнен с отключённым xfail: failed, 2026-10-09 14:17:46.676–14:17:48.018 +03:00. Проверка выявила корневой массив вместо опубликованного объекта.
- Подготовка и резервная очистка прошли; последнее чтение списка подтвердило 200 и `[]`.

Минимальная очищенная выдержка; служебные поля и чувствительные значения опущены:

```text
OpenAPI 200 schema: $ref → PlayerResponseDTO (object)
GET /api/automationTask/getAll → 200
live root type: array
empty final list: []
```

Фрагмент ответа повторного прогона: HTTP **200**. Остальные поля опущены; токен скрыт, пример ID заменяет фактический идентификатор.

```json
[]
```

## Проверка исправления

- Обновить опубликованный контракт и его версионируемый снимок; contract-тест должен проверять исправленную схему.
- Проверить пустой массив, несколько игроков, одинаковые имена и уникальность ID.
- Сохранить проверки неизменности состояния при повторном чтении; не переводить endpoint на одиночный объект.
