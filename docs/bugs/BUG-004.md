# BUG-004. Конфликт требований к getOne: 200 в задании, 201 в OpenAPI

## Краткое описание

Для `POST /api/automationTask/getOne` задание требует 200, а OpenAPI публикует 201. Стенд соответствует OpenAPI и расходится с приёмочным требованием задания [PROFILE-01](../api-spec.md#profile-01).

## Оценка серьёзности и приоритета

Предлагаемая оценка, не утверждённая владельцем: **Severity — Minor для конфликта требований; Priority — P2**. Профиль читается, но приёмочный критерий и опубликованный контракт требуют разных кодов. До решения владельца это не однозначно установленный дефект реализации платформы.

## Окружение

- Стенд: `https://testslotegrator.com`.
- Контрактное воспроизведение: 2026-10-09, 14:17:49.778–14:17:51.566 +03:00 (Europe/Istanbul); отдельный предшествующий E2E — 13:36:35–13:36:57 +03:00.
- Build/version/commit сервиса: **неизвестны**; источник версии развёртывания недоступен. `info.version: 1.0` в OpenAPI — версия документа, а не сборки backend.
- Источник требований: [сохранённый OpenAPI](../../src/test/resources/contracts/players-openapi.json), задание и явно принятые правила [спецификации](../api-spec.md).

Приведённые результаты относятся только к указанному прогону 9 октября 2026 года.

Повторный строгий прогон 9 октября 2026, 16:19–16:23 +03:00 подтвердил то же расхождение. Тесты выполнялись без преобразования падений в XFAIL; подготовка и резервная очистка завершились без ошибок.

## Предусловия

Действующий Bearer, собственный созданный игрок; его email известен из исходного запроса.

## Шаги воспроизведения

1. Подготовить собственного игрока и подтвердить его существование.
2. Передать его email в JSON POST `getOne`.
3. Проверить исходный HTTP-код; после проверки удалить собственные данные.

## Минимальный HTTP-запрос

Пример HTTP-запроса с действующим токеном и email заранее созданного собственного игрока. Значения в угловых скобках заменяются локально. После проверки собственного игрока нужно удалить адресно.

```http
POST /api/automationTask/getOne HTTP/1.1
Host: testslotegrator.com
Authorization: Bearer <ACCESS_TOKEN>
Content-Type: application/json

{"email":"<OWN_PLAYER_EMAIL>"}
```

## Фактический результат

Независимый `profileStatusMatchesAssignment` получил **201** вместо 200 и завершился **failed** по проверке кода при отключённом xfail. Подготовка и резервная очистка прошли; последний getAll вернул 200 и `[]`. В предшествующем E2E все 12 запросов профиля также вернули 201.

## Ожидаемый результат

Приёмочная проверка проекта требует ровно **200** по заданию. **Конфликт источников:** OpenAPI публикует 201, совпадающий со стендом. Владелец задания должен подтвердить нормативный код; до этого расхождение нельзя однозначно приписывать ошибке платформы.

## Влияние

Результат не удовлетворяет критерию задания. Потребители получают разные ожидания из задания и Swagger.

## Технический анализ

- **Подтверждено:** задание требует 200, опубликованный код и live-ответ равны 201.
- **Неизвестно:** причина рассогласования источников и реализация контроллера.
- **Рекомендация:** согласовать с владельцем задания, какой код нормативен. Если подтверждён 200, привести к нему реализацию и OpenAPI. Если утверждён 201, явно исправить критерий задания и связанную проверку; одного наблюдения стенда для изменения требования недостаточно.

## Обходной путь

Функциональный адаптер допускает опубликованный в задании 200 и наблюдаемый 201, чтобы проверять поля, идентичность и жизненный цикл. Соответствие заданию проверяется отдельно.

## Доказательства

- Метод [PublishedPlayersContractIT#profileStatusMatchesAssignment](../../src/test/java/qa/slotegrator/tests/contract/players/PublishedPlayersContractIT.java) выполнен с отключённым xfail: failed, 2026-10-09 14:17:49.778–14:17:51.566 +03:00.
- Подготовка и резервная очистка прошли; DELETE при очистке вернул 200. Последнее чтение списка подтвердило 200 и `[]`.

Минимальная очищенная выдержка; служебные поля и чувствительные значения опущены:

```text
POST /api/automationTask/getOne
assignment expected: 200
OpenAPI documented:  201
live actual:         201
```

Фрагмент ответа повторного прогона: HTTP **201**. Остальные поля опущены; токен скрыт, пример ID заменяет фактический идентификатор.

```json
{"id": "0123456789abcdef01234567"}
```

## Проверка исправления

- Зафиксировать решение владельца по конфликту источников; при подтверждённом требовании 200 запустить контрактный метод и получить 200 на собственном существующем игроке.
- Проверить отсутствие изменения состояния при чтении и корректный профиль цели.
- Сверить успешный код в реализации, OpenAPI и согласованном задании; ошибки поиска и авторизации не подменять этим случаем.
